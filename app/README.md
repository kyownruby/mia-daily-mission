# Dailyn（デイリン）

ゲームの「デイリーミッション」をモチーフにした、タスク管理Webアプリです。
名前の由来は Daily（毎日）＋ n（n回やる＝カウンター式ミッション）。
タグラインは「数えて、貯めて、レベルアップ」。
タスクを達成してPtを貯めると経験値（EXP）が入り、アカウントのレベルが上がります。
進捗は Cloud Firestore に保存され、同じアカウントでログインすれば複数デバイスで共有できます。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `index.html` | 画面（ログイン画面・メイン画面） |
| `style.css` | スタイル・進捗バー・レベルアップ演出 |
| `app.js` | 認証・Firestore同期・Pt/EXP/レベルのロジック |
| `firebase-config.js` | Firebase の設定値（**要書き換え**） |
| `firestore.rules` | Firestore セキュリティルール（コンソールに貼り付け） |

## セットアップ手順

### 1. Firebase プロジェクトを作成

1. [Firebase コンソール](https://console.firebase.google.com/) で「プロジェクトを追加」
2. プロジェクト作成後、「ウェブアプリを追加（`</>` アイコン）」でWebアプリを登録
3. 表示される `firebaseConfig` の値を `firebase-config.js` に貼り付ける

### 2. Authentication を有効化

1. コンソールの「構築 > Authentication > ログイン方法」を開く
2. 以下の2つのプロバイダを有効にする：
   - **Google**
   - **メール / パスワード**

### 3. Cloud Firestore を有効化

1. コンソールの「構築 > Firestore Database」で「データベースを作成」
2. 本番環境モードで作成（ロケーションは `asia-northeast1` など）
3. 「ルール」タブに `firestore.rules` の内容を貼り付けて公開

### 4. 動作確認（ローカル）

このフォルダを静的サーバーで配信します（ESモジュールを使うため `file://` 直接開きは不可）：

```bash
cd app
python3 -m http.server 8000
# → http://localhost:8000 を開く
```

※ Googleログインを使う場合、Firebase コンソールの
「Authentication > 設定 > 承認済みドメイン」に `localhost` が含まれていることを確認してください
（デフォルトで含まれています）。

### 5. 公開（任意）

Firebase Hosting / Vercel / Netlify / GitHub Pages など、静的ホスティングにこのフォルダを配置すればOKです。
公開ドメインを「承認済みドメイン」に追加するのを忘れずに。

## 遊び方

1. Google または メール&パスワードでログイン
2. ミッション（タスク）を追加（報酬Ptは5Pt単位・最大100Pt）
   - **1回で完了**：従来どおり、完了ボタン（✓）1回でクリア
   - **カウンター式**：「○○をn回する」形式。目標回数（1〜999）を設定する（報酬Ptの初期値は25）
   - **サブタスク**：1回完了式のミッションには、サブタスク（子タスク）を複数付けられる。全部チェックすると親の完了ボタンが押せるようになる（Ptは親のみ）。**サブタスクのチェックは日付が変わっても維持される**ので、やり残しは進捗そのまま翌日に持ち越せる。一覧では折りたたみ表示（▶で開閉、閉じたままでも進捗表示）
   - 操作ボタンはアイコン（✓完了 / ペン編集 / ×削除）。**削除は確認なしで即実行**なので注意
   - **並び替え**：各行の左端のハンドル（⋮⋮）をドラッグすると、ミッション・プリセット・サブタスクの順番を入れ替えられる（マウス・タッチ両対応。並び順はクラウドに保存され、他の端末にも反映される）。サブタスクは一覧を開いた状態でも、編集フォーム上でも並び替えできる
   - **プリセット**：よく使うミッションをプリセットタブに登録しておくと、「デイリーへ」「メインへ」のワンタップでミッションに追加できる（同じプリセットを何回でも追加OK。追加後はプリセットと独立して扱われる）。サブタスク構成と期限（追加日から〇日後＋時刻・無期限）も登録でき、**「メインへ」追加時にその日を起点に期限日が計算**される（時刻はそのまま引き継がれる）
3. タスクを完了すると本日のPtが貯まる（1日上限100Pt・超過は切り捨て）
   - カウンター式は「＋／－」ボタンでカウントを進め、**目標回数に達すると完了ボタンが押せる**ようになる（Ptは完了時にまとめて付与）
4. 本日のPtが 25/50/75/100 に達するごとに 10EXP、100Pt達成でさらにボーナス +20EXP
5. EXPが貯まるとレベルアップ！（完了を取り消すとPt・EXP・レベルも巻き戻ります。カウンター式のカウントは維持されるので、すぐ再完了できます）
6. 日付（Asia/Tokyo基準）が変わると、本日のPt・カウンターのカウントはリセット。レベルはそのまま
   - **完了済みだったミッションは一覧から消える**（その日のぶんは終わったものとして片付けられる）。毎日やるミッションはプリセットから足し直すのが基本の使い方
   - **やり残した（未完了の）ミッションは残り、サブタスクの進捗もそのまま**翌日に引き継がれる

### メインミッション（長期目標）

- 「メイン」タブで、日をまたいでもリセットされない長期目標を管理できる（1回完了式／カウンター式／サブタスク対応はデイリーと同じ）
- **期限（締切日）を設定できる**（無期限も可）。期限切れは赤いバッジで知らせるだけで、自動削除や失敗処理はない（残り3日以内は黄色）
- 期限には**時刻（hh:mm）も任意で付けられる**。時刻を付けるとその時刻を過ぎた時点で期限切れ、時刻なしならその日いっぱいが期限。表示は「期限 2026-08-15 18:30」のようになり、画面を開きっぱなしでも1分ごとに表示が更新される
- 完了するとPtが入るが、**デイリーの100Pt上限とは別枠**（「本日のPt」バーには影響しない）。EXPは25Ptごとに10EXP（デイリーの100Pt達成ボーナスは対象外）
- 移動アイコン（⇄）で**デイリー ⇔ メインの引っ越し**ができる。設定（名前・タイプ・Pt・目標回数・サブタスク構成・期限）は保持され、進捗はリセットされる（期限はデイリー側では表示されないけど保持されていて、メインに戻すと復元される）
- **並び順**：期限（日付・時刻）を設定・変更すると、**一覧全体が自動で期限が早い順に並び直る**（同じ日なら時刻が早いほうが先、時刻なしはその日の最後、期限なしは末尾にまとまる）。新規追加・デイリーからの移動・プリセットからの追加でも、期限つきなら同じように整列される。期限を使わない操作（名前の変更など）では並びは変わらないので、ハンドルでの手動並び替えもそのまま使える

## 調整できる定数（app.js 冒頭）

| 定数 | 意味 | デフォルト |
| --- | --- | --- |
| `dailyPtCap` | 1日のPt上限 | 100 |
| `ptStep` | タスクPtの設定単位 | 5 |
| `expPerStep` | 25Ptごとの獲得EXP | 10 |
| `stepPt` | EXP付与のPt区切り | 25 |
| `dailyBonusExp` | 100Pt達成ボーナスEXP | 20 |
| `LEVEL_TABLE` | レベルごとの必要EXP（最後の値を以降繰り返し） | 50, 80, 120, ... |
| `BASE_TIMEZONE` | 日次リセットの基準タイムゾーン | Asia/Tokyo |
